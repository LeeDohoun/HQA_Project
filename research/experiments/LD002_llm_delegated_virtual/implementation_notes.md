# LD002 implementation and runbook

The immutable contract is `preregistration.md` at `78174f5`, SHA-256
`46982e5f8716332c661b208989515a319f343f69efa1509b22f06b2803154332`.
It has not been edited. This implementation is forward only. Development opened
no real price archive, real holdout session, network connection or model process;
it did not stage, commit, install or deploy anything.

## Files and boundaries

`backtesting/experiments/ld002/` contains the candidate builder and v1 rendering
adapter, Codex attempt journal, deterministic close accounting, 200 conditional
replacement paths, daily workflow, H1 snapshot/distribution readers and producer,
activation gates and final evaluator. The sole existing-code change is LD002's
addition to `ordering.py`: exactly LH003's mandatory AV001/EV001/linked-AV002
releases, also on direct holdout access under the common ordering lock.

The v1 Korean prompt, fixed re-ask, schema template and actual renderer live in
`prompts/`. Every decision records their hashes; code checks require these files
and the implementation to be committed before a real call. No commit was made
as part of this delivery. Existing LH001 event detection, LH003 immutable storage,
snapshot input view, rule-S financial loader and mechanical amendment validator,
v2 costs and the shared verified calendar are reused without editing them.

`scripts/ld002/` provides the CLI. `deploy/ld002/` has four lab service/timer
pairs and installation notes. Five `tests/test_experiments_ld002_*.py` files plus
`tests/ld002_fixtures.py` exercise only labelled fixtures and Python fakes.

## Operator runbook

All commands are plans unless `--execute` is supplied **after the subcommand**.
For example, these commands read no archive or credentials and write nothing:

```bash
venv/bin/python -B -m scripts.ld002 input-seal --fw001-dir /srv/ld002-feed/fw001
venv/bin/python -B -m scripts.ld002 decide
venv/bin/python -B -m scripts.ld002 ledger-finalize --status-file '/srv/ld002-feed/status/{day}.json'
venv/bin/python -B -m scripts.ld002 evaluate
venv/bin/python -B -m scripts.ld002 activation-check
```

Before 2026-11-13 23:59:59 KST, the operator must finish the following on the
research account of `hqa-server`. These are future operator actions, not completed
deployment evidence:

1. Review and commit code/prompts, install the separate `/opt/hqa-ld002` checkout,
   select the same research account as LH003, and authenticate Codex there.
   Keep credentials in that account's existing home, outside the code root.
2. Verify the transferred full archive inventory and shared heavy-lock inode.
   An ordinary JSON transfer manifest has aware `verified_at`, actual

   Run `distribute --source-dir <raw-transfer> --sync-manifest <manifest>

   committed with the delivery, never regenerated by a distribution command.
   After activation, use the start/amendment chain. Verify that reference against
   both disk and process-load hashes before raw access, before manifest sealing
   and before completion. FW001's actual reader module is included. A changed
   import cannot be certified by restoring its file; restart with approved code.
   A failed latest publication blocks older ones. Daily jobs never reopen raw
   archives, even for inventory or hashing.
3. Verify the three predecessor releases. Run `seal-holdout --source-dir
   <raw-transfer> --state-dir <state> --execute` exactly once. The canonical
   repository's ordering lock covers `HoldoutSession(LD002)` and its canonical
   holdout ledger append. The result is `<state>/holdout_snapshot` plus
   `holdout.json`. Production verifies every H1 session's two markets and both

4. Run synthetic format checks only, maximum ten reserved attempts in this same

5. Produce section 10 evidence. `activation.check` requires non-synthetic live

6. Run `activation-check --evidence <evidence.json> --state-dir <state> --execute`.

   produces `not_started`. Then separately review/install the systemd templates

Daily sequence: finalize the oldest missing close, build/seal the new input under
the existing nonblocking heavy lock before 10:00, then decide outside that lock
before 12:00. The finalizer resumes one oldest unfinalized session per invocation,
including after a multi-day outage. Historical decisions remain missing; no
reconstruction supplies trades. An absent predecessor seals `ledger_not_final`
for the new day. Timers repeatedly reuse the same durable state and call budget.

The official daily sidecar is mandatory. It contains `day`,
`coverage_verified: true`, `official_source`, `stocks` mapping every KRX code to
boolean `halted`, `limit_up`, `limit_down`, and explicit `corporate_actions`.
Store immutable `status/YYYY-MM-DD.json`; `{day}` and `{stamp}` in the CLI path
expand to ISO and YYYYMMDD. The raw daily loader alone does not certify exact
limits or corporate actions. Do not substitute a percentage tolerance or an
assumed empty list. Each close seal stores the actual prices, actions and source
hashes as well as its previous-state and decision hashes. Read a finalized book
through `ForwardRunner.ledger`: its canonical value combines the immutable state,
completion marker and finalization acknowledgement. The raw state JSON alone
is a candidate. Preserve publication directory mtimes when backing up state.
Pre-trade NAV and previous-state hashes avoid storing a second complete position
tree for each of the 612 books; prices and official actions reproduce that state.

Corporate actions require a unique `id`, `code`, `effective_day` and
`official_source`. Splits supply `factor` and, for fractional entitlements,
`fraction_cash_price`. Dividends/mandatory rights supply an earlier sealed
`entitlement_day` and `cash_per_share`; rights also supply `shares_per_share`
and an official `reference_price` if they create a new position. Fractional rights
require an explicit official `fraction_cash_price`; integer shares are floored
and the fraction is paid at that price. Each book's own
entitled quantity determines its shares/cash. Recovery supplies officially
confirmed `cash_per_share` and removes the remaining position, including a
confirmed zero recovery. Discretionary rights exercise is not inferred. A
fractional rights entitlement without an explicit official cash-in-lieu price
refuses, rather than inventing shares/cash. No adjusted return multiplies actual
shares in ledger accounting.

On/after 2027-11-23 00:00 KST run `evaluate --state-dir <state> --execute`.
It reads only sealed ledgers, input/decision publications, attempts and audit
artifacts. It checks the daily hash chain, freezes out later ledger seals, and
publishes one `policy` row to the canonical registry. A matching existing result
can repair publication; an existing row with missing/different state refuses a
new evaluation. Stopped experiments have `verdict: null`; the registry's required
verdict column contains their operating status, with `final_verdict: null` in
metrics. Primary statistics never use a shortened completed-window sample.

Price/action corrections use `ledger-finalize --day YYYY-MM-DD
--status-file <correction-sidecar> --audit-correction --execute`. An audit starts
from the original prior seal and original decision; it cannot change future
inputs, official trades or termination. It writes a new hash-named audit artifact,
and the final report includes its NAV differences. A stop requested independently
by an operator uses `ForwardRunner.terminate('forward_aborted', reason=...)`
under the state lock; it has the same recognition-time liquidation procedure.

For a reviewed future **data-only** statutory/calendar update, `amend` delegates
to LH003's AST-restricted amendment validator; supply `--path`, `--legal-source`,
`--effective-date`, `--changed-at` and `--execute`. It records before/after hashes;
it never edits those shared modules. Start a fresh process afterwards. Other
code drift refuses; a recorded bug fix requires a separately reviewed code-pin
workflow, not changing the frozen start or weakening this validator.

## Interpretations fixed before first actual-data call

1. Both daily cutoffs are strict. A kernel private-directory publication timestamp
   plus a conservative one-second precision interval must lie wholly before the
   cutoff. A prepared file without a completion marker is not sealed; late
   candidates are exposed as `reconstructed` by the decision reader. The activation
   deadline itself is inclusive at the stated second.
2. T0's daily return compares post-fill NAV to the initial 100 million, so it
   includes initial costs. Index reporting instead enters at T0 close and excludes
   dividends. No cash interest or deposits are added.
3. Each scenario computes NAV after official share/cash events and before trades,
   using raw T-close marks. No quantities or NAV-based limits are fixed at noon.
4. The exact step order is minimum trade, uniform gross-turnover scaling,
   individual ADV cap, execution blocks, actual net sales, uniform cost-inclusive
   buy-cash scaling, integer floor. Unfilled/rounded amounts never increase another
   trade. Halt/missing-row positions are frozen at step 3. Limit-up/down orders
   still consume planned turnover before their execution block.
5. Exactly 0.5% is tradeable. Minimum-trade comparisons are strict and share
   counts use floor directly, without a tolerance that could promote an
   under-threshold delta or fraction to a trade. Dust is not reallocated.
   Liquidation omits minimum trade and gross turnover, retaining 1% ADV and blocks.
6. An outside-U existing quantity can stay or decrease, including in random paths.
   Any requested increase is ignored and logged. The private seal keeps ADV for
   all observed stocks so outgoing EW/AV/random holdings can be sold even when
   absent from the displayed LD candidate table. It is not additional prompt data.
7. Common-share eligibility follows the established stock-only KRX archive,
   code suffix 0 and SPAC/REIT/ETF/ETN name exclusions, plus explicit security-type
   metadata when present. Explicit halt metadata takes precedence; the existing
   archive's zero-volume proxy is used when it lacks a halt field. There is no
   HC002 1,000-KRW floor or financial-industry
   exclusion. Security names are required for these exclusions; other unavailable
   table values render as `자료 없음`.
8. ADV needs all twenty verified preceding sessions, including T-1. A row gap is
   not zero turnover. The top-400 selection sorts descending ADV, then code; the
   displayed U/table and replacement pools use lexical code order.
9. 250-day returns require 251 close-known sessions. Returns use complete stored
   change-rate chains. The 52-week high uses 250 sessions of raw intraday highs
   rescaled by the return chain; 60-day volatility is sample daily standard
   deviation, not annualized. Incomplete windows stay unavailable.
10. Financial dates use S and the existing CFS/OFS/quarter derivation. Date-only
    publications on the T-1 close date cannot prove pre-close availability and are
    excluded, just as in LH003. YoY fields retain the existing quarterly loader's
    bounded/nonpositive-base conventions; operating margin uses the actual
    derived quarterly operating income divided by revenue, unavailable at zero
    revenue. This is not a claim to reconstruct unknown historical vintages.
11. Disclosures use the entire specified T-1 receipt day. Real receipt timestamps
    are required when enabled; date-only listings do not become invented midnight
    timestamps. Without verified full-list/time coverage, omit this item for the
    whole observation window and freeze that choice at activation.
12. Disclosure ties sort timestamp, receipt number, code. Keep the first three
    per company and then the first 300 globally; do not prefer any event category.
13. Breadth is the strict-positive one-day-return fraction among that market's
    observed common stocks with a known return; flat stocks remain in its
    denominator. Candidate membership does not determine market breadth.
14. Holding days count exchange sessions including the entry session. Memo memory
    is five prior trading-day slots; an invalid/missing day has an unavailable
    memo, not a replacement from an older valid output. NAV history uses twenty
    finalized trading-day slots.
15. A busy heavy lock, unavailable input source or missing prior finalized ledger
    is a retryable deferral before the 10:00 input-seal cutoff. Timer invocations
    retry readiness and input building through 09:55; the input unit wants and
    runs after the finalizer. An 08:45 miss can therefore seal at 09:00. At or
    after 10:00, seal the omission (`ledger_not_final` when the predecessor is
    still unavailable, otherwise `input_not_sealed`); never reconstruct a past
    decision. Input/decision retries reuse exact seals. A crash between a durable
    candidate and its completion receipt can finish publishing that exact
    candidate before its cutoff, without rebuilding or calling again. An already
    rejected/late publication is never re-completed.
16. Attempt reservations are durable before process creation. Timeout, quota,
    process failure and interruption all consume a slot. Only the same fixed
    re-ask can use the second slot. Format attempts share the journal and have
    a separate ten-attempt ceiling. At most two calls per registered official
    decision day enforces the daily-window budget without guessing 2027 sessions.
17. SeedSequence(0).spawn(200), then PCG64 per path, is serialized with the ID map.
    Process new IDs lexically with one uniform draw from the current sorted pool.
    Invalid days consume no draws and do not reset the previous-valid-ID set.
18. A retained ID with no mapping because of an earlier shortage remains cash.
    Re-entry after leaving a valid output is a new ID. Missing mappings retain
    their original conviction in the denominator, so shortages do not redistribute.
19. Empty decomposition holdings mean target zero, still subject to LD limits;
    existing shares therefore can take multiple days to become cash. It is not
    an instantaneous liquidation or a pure timing experiment.
20. EW enters only on T0 and subsequent first monthly sessions. Missing input on
    a scheduled entry means hold until the next scheduled rebalance. Its per-name
    cap is still 10%, including a hypothetical U smaller than ten, without minimum
    trade/gross-turnover limits. AV follows newly completed FW001 target identities,
    using their capped weights and the same integer/cash/ADV/block accounting;
    it also has no LD minimum/gross-turnover limit.
21. D is inclusive at 25%, with the initial NAV in its peak. Recognition uses actual
    ledger finalization time sampled after the state and completion marker are
    durable, not a timestamp taken before writing or the old price date. Every
    daily book has its own immutable completion marker and finalization
    acknowledgement. A crash before the acknowledgement finishes finalization
    at recovery time; no earlier recognition is invented. A crash after it
    recovers its exact time and already sealed liquidation start before publishing
    the separate stop record; later calendar updates do not recalculate it. Exactly noon uses the next
    verified trading session. A weekend recognition uses the next session too.
22. The earliest operating stop is immutable. Before evaluation and automatic
    finalizer resume, recover all durable ledger approvals and model-change
    records under the state lock, including an approval on the last observation
    day whose separate stop publication crashed. Compare original recognition
    times, preserve the approval's sealed liquidation start, and never replace
    it with recovery time. LD cost books share that signal; comparators have no
    independent D test.
23. A stop recognized during a session stops new buys and freezes random/decomposition
    decisions for that session even if an earlier output validated. After noon,
    LD holds until next-session liquidation. A stop first recognized after a close
    does not cancel that close's already sealed decision retroactively.
24. Missing input does not justify using stale ADV for compulsory liquidation:
    independently seal the exact prior twenty-session ADV and its hashes. Without
    usable ADV, that name is explicitly blocked. Liquidation cannot borrow assumed
    proceeds from blocked sales.
25. Halted/missing/delisted-unconfirmed positions use their own last confirmed raw
    close, with both session and calendar age, within a day having both verified
    market close files. An absent/incomplete market file blocks daily ledger
    finalization entirely; next-day input and LLM execution remain gated by
    `ledger_not_final` until the complete close data arrives. Never seal a primary
    using a partial-market valuation. Recovery replaces shares
    with official cash. Cash/share entitlements are recognized at the sidecar's
    official effective date using each book's earlier entitled shares; no return
    adjustment is also applied. Before T0 there were no experimental shares:
    pre-T0 entitlement quantities are zero, with an explicitly absent prior-ledger
    hash rather than a fabricated historical book. Fully extinguished zero-cash books stay at zero
    with subsequent zero returns rather than producing 0/0 observations.
26. All 612 books (four named policies plus 200 replacements, each at three costs)
    use independent quantities/cash. No shared x1 trade quantities or tax scaling
    is used. Calendar/tax coverage failures refuse, rather than carrying 2026
    assumptions into 2027.
27. Official daily corrections produce only one-day audit recalculations from the
    frozen predecessor, not revised feedback or revised stop times. Their full NAV
    differences are linked from the final report.
28. Undefined NW variance, fewer than 150 timely valid decisions (valid all-cash
    outputs count), a missing required day or either market makes `insufficient`.
    Invalid LLM days with intact ledgers still enter the daily difference series.
    No finite-sample correction, normal one-sided p, strict t>3, >= ties for random
    controls and <=5% control share are used. x1.5 compares its own EW scenario;
    x2 and lags 10/20 do not change judgement.
    Audit/correction files can report recovered-file coverage and one-day NAV
    differences, but cannot establish judgement eligibility for a primary ledger
    built from incomplete inputs. Such legacy primaries remain `insufficient`,
    even when all missing files arrive before freeze. Preserve their original
    hash chain for descriptive evaluation; never repair feedback/trades/stop or
    approve them for next-day inputs. New primary seals require both markets.
29. Sensitivity writes unresolved final residual values to zero at 2027-11-15
    close only, on every policy/path/cost scenario; no past fills are rerun. Only
    a base pass lost under sensitivity becomes `delisting_sensitive`; an already
    insufficient base remains insufficient.
30. The preregistration names a freeze date without a time; use 00:00 KST at the
    start of 2027-11-23, excluding later seals and later-recognized stops from the
    frozen result. Status and verdict remain separate.
    The canonical single row cannot be bypassed by losing/rolling back local state.
31. The lab account name in unit templates is a placeholder for the actual LH003
    research account. MemoryMax 1536 MiB follows LH003's capacity envelope, not a
    measured guarantee for this deployment. Actual resource/restart/priority gates
    remain mandatory; fake measurements cannot establish readiness.
32. Hash the invoked executable and, for a Node launcher, its packaged native
    executable(s); an unresolved native path refuses identity. Visible model
    argument, CLI version and executable/artifact hashes cannot
    detect provider internal-weight changes under the same public identity.
