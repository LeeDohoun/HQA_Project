# HQA 변화 흐름 (2026-02 ~ 2026-10-29)

이 문서는 HQA가 **처음에 어떤 방식이었고, 어떤 결과가 나왔고, 그 뒤 무엇을 왜 바꿨는지**를 시간순으로 정리한 기록입니다. 과거부터 현재까지의 흐름을 한곳에서 파악하는 것이 목적입니다.

- **근거:** GitHub PR과 커밋, 저장소 문서(`docs/`), 백테스트 보고서, PAPER 운영 기록을 근거로 썼습니다. 괄호 안의 PR 번호와 커밋으로 원문을 확인할 수 있습니다.
- **이유 표기:** 바꾼 이유가 기록에 없으면 **"기록 없음"**으로 적었습니다. 추정은 추정이라고 밝혔습니다.
- **작성 기준일:** 2026-10-26에 쓰고, 10-27에 분석가 RAG 실험 결과를, 10-29에 모의투자 11일차까지의 결과와 구조 수정 실험의 중간 결과를 더했습니다. 모의투자 관찰(20거래일)은 진행 중이고, 2026-11-10에 끝납니다.
- **이름 표기:** 사람 이름 대신 GitHub 계정 이름을 그대로 적었습니다.

## 1. 단계별 상세

### 1.1 RAG 파이프라인 시작 (2026-02 ~ 03 초)

**방식**
- **RAG v0.2.0** (PR #1, 2/6, are012)
  - 문서 인식: PaddleOCR-VL OCR
  - 임베딩: Snowflake Arctic 한국어 임베딩
  - 리랭커: Qwen3-Reranker
  - 이미지 처리는 빼고 텍스트만 다룹니다.
- **LLM 스택 전환** (PR #3, 3/6, are012): Gemini와 transformers에서 **Ollama(로컬 LLM·임베딩)와 CrossEncoder 리랭커**로 바꿨습니다. Google API 키 의존을 없앴습니다.
- **LLM Provider 패턴** (PR #12~14, 3/16): Ollama와 Gemini를 바꿔 끼울 수 있게 했습니다.

**결과:** 검색 품질이나 성능 수치는 기록에 없습니다.

**바뀐 이유:** PR #3에 따르면 외부 API 키 의존을 없애고 로컬에서 실행하기 위해서입니다.

### 1.2 RAG 데이터 파이프라인으로 축소 (3/12 ~ 3/17)

**방식**
- **수집기 추가** (PR #6, 3/12): 네이버 뉴스, DART 공시, **네이버 종목토론방** 수집기와 RAG 코퍼스 빌더를 추가했습니다.
- **저장소 축소** (PR #9~#15, 3/14~3/17): 백엔드 API, Celery, DB, Next.js 프런트, Docker 등을 제거하고, 소스별 RAG 자산(JSONL과 가벼운 벡터 저장소)만 남겼습니다.
- **가벼운 벡터 저장소** (3/16 커밋 `4841390`): 뉴스, DART, 종토방별로 독립 벡터 저장소를 만들게 했습니다. 이때 벡터는 의미 임베딩이 아니라 **단어를 해시로 256칸에 담는 방식**입니다.

**결과:** GPU 없이 어디서나 도는 수집·RAG 파이프라인이 됐습니다.

**바뀐 이유** (PR #11 설명): "무거운 런타임·인프라와 GPU 의존 구성 요소를 없애 유지보수를 단순화하고, 어디서나 돌아가는 최소 파이프라인을 만들기 위해서"입니다.

**나중에 드러난 영향:** 10/26 점검에서 이 벡터 검색이 사실상 단어 일치 검색이라는 것이 확인됐습니다(1.11).

**참고:** 3/18 커밋(`2e0d615`) 메시지에 "종토방은 아직 연도별 수집 불가"라고 적혀 있습니다.

### 1.3 수집 품질과 계층 분리 (3/24 ~ 4/3)

**방식**
- **수집 계층 도입** (PR #17~#20, 3/24): 수집과 원본 저장(Layer 1)과 RAG 재구성·검색(Layer 2)을 나눴습니다. 일반 뉴스와 차트 소스도 추가했습니다. 벡터·BM25 검색은 하나의 통합 검색 서비스로 묶었습니다.
- **품질 검사** (PR #23~#37, 3/29~3/30): 원본 품질 검사 도구를 만들고, DART·뉴스·종토방 파싱을 강화했습니다.
- **병합과 연결** (PR #38, 4/1): `rag-data-pipeline`을 병합했습니다. 4/3에는 are012 계정이 테마 대상 저장, RAG 흐름 통일, 데이터 파이프라인과 에이전트 연결을 했습니다.

**바뀐 이유** (PR #20 설명): 수집과 재구성을 독립시키고, 중복 제거와 소스 처리를 개선하고, 차트 데이터를 지원하기 위해서입니다.

  - **결정:** 퀀트, 차티스트를 거쳐 RiskManager가 최종으로 매수·매도·보유를 결정했습니다.

  - KIS 차트·스케줄러 (PR #39~#41, 4/6)
  - 모노레포 통합 (PR #43, 5/7): 프런트, 백엔드, AI 서버를 한 저장소로 합쳤습니다.
  - 화면 개편, 종목 DB, 약관, 홈페이지 (5/17~5/25)

  - 에이전트 런타임을 main으로 옮기고 AI 런타임 API를 열었습니다 (PR #53, #54).
  - 차티스트 가격 스냅숏 (#56), 성향별 매매 신호 실행 (#55), 대시보드 분석 (#58)
  - 데모용 분석·매매 흐름 (#63), KRX·DART 수집 (#64)
- **2024 백테스트 결과** (PR #61, #62, 6/3~6/7): 멀티 에이전트·기술적 지표 실행 결과와 비교표, HTML 보고서(`artifacts/backtesting_2024_report/`)를 추가했습니다.

**결과:** 데모 가능한 분석·매매 흐름과 2024 백테스트 보고서가 나왔습니다. 다만 9월 점검에서, 이 시기 연구 실행들은 결정일 **당일 문서까지 쓴** 버전(v3)이라 다시 돌려야 한다는 점이 확인됐습니다(1.7).

### 1.5 LangGraph 매매 흐름 삭제 (6/15 ~ 6/16)

**방식**
- **"로컬 Ollama용 에이전트 정리"** (커밋 `6ef8c54`, 6/15, are012)
  - `theme_orchestrator.py`(1,248줄)와 LangGraph `graph.py`(973줄)를 삭제했습니다.
  - 분석가의 RAG 출처를 DART·뉴스·종토방으로 좁히고, 웹 검색 대체 경로와 차트 이미지 분석을 뺐습니다. 계획 문서는 `docs/superpowers/plans/2026-06-15-analyst-dart-news-forum-only.md`입니다.
  - 이 커밋은 9/6 PR #65로 main에 들어갔습니다.
- **증거 파이프라인 재구성** (커밋 `e828d63`, 6/16): 의미 임베딩(OllamaEmbeddings)과 CrossEncoder 리랭커 경로가 이때 코드에서 빠졌습니다.
- **CDE 제출** (`cde_2026` 브랜치, 6/23): 제출 자료를 별도 브랜치에 정리했습니다.

**결과:** 분석가 에이전트의 RAG 검색은 남았지만, **그것을 매매에 잇는 흐름이 사라졌습니다.** 이때부터 매매 경로에서 RAG가 빠졌습니다.

**바뀐 이유:** 두 커밋 모두 설명 본문이 없어 **기록 없음**입니다. 제목상으로는 로컬 Ollama 작업 흐름에 맞춘 정리입니다.

### 1.6 Luna PAPER 런타임 (9/5 ~ 9/8)

**방식**
- **공유 분석 런타임** (커밋 `7e8f513`, 9/5)
  - 종목 분석은 계좌들이 함께 쓰고, RiskManager 결정만 계좌별로 따로 합니다(`SharedAnalysisService`).
  - API 예산 원장, 버전이 붙는 PAPER 계획, 독립 손절·청산 모니터, 체결 대조, 오프라인 평가 도구를 넣었습니다.
- **사건 근거 파이프라인** (커밋 `cd18b7a`, 9/5, `docs/event-data-pipeline.md`)
  - 분석 시점에 알 수 있던 최신 문서를 크기가 제한된 사건 묶음(종목당 최대 8개)으로 만듭니다.
  - 분석가는 사건을, 퀀트는 재무 수치를, 차티스트는 사건 뒤 주가 반응을 받습니다.
  - **유사도 검색(RAG)이 아니라 규칙으로 고르는 결정적 준비입니다.**
- **정리** (9/6): 시장 벤치마크와 기업 행위(유상증자 등) 안전장치를 넣었습니다(`ce81b3a`). 수집·평가 진입점을 정리하고 `requirements.txt`에서 langgraph를 뺐습니다(`cd8ad65`).
- **병합:** PR #65(9/6)로 main에 병합했고, PR #67(9/8)로 대시보드 분석을 복구하고 주문 연동 결함을 고쳤습니다.
- **모델:** 설계는 OpenAI `gpt-5.6-luna` 기준이었지만 키가 없어 실제로는 돌리지 못했고, 로컬 시험은 Ollama로 했습니다.

**결과:** 실제 주문 직전 단계까지의 구조가 갖춰졌습니다. 흐름은 순서가 고정된 코드로 실행되고, LangGraph는 쓰지 않습니다.

**바뀐 이유** (설계 문서 기준): 결정적 준비, 판단 시점 이전 정보만 쓰는 시점 정합, 감사 가능성(실제로 넣은 근거를 기록), 예산 관리입니다. **"RAG를 뺀다"는 결정 기록은 없습니다.**

### 1.7 9월 점검과 수정 (9/21 ~ 9/29, `feat/dohoon-changes`)

### 1.12 분석가 RAG 비교 실험 결과 (10/26 ~ 10/27)

**방식**

**결과**

| 지표 | 기준 | RAG |
|---|---:|---:|
| 총수익 | −1.72% | −1.02% |

**판정:** 지금 형태의 분석가 RAG는 순위 신호를 의미 있게 바꾸지 못했고, 분석가 호출 비용은 약 2.5배가 됩니다. 채택 근거가 없습니다.

  - RiskManager는 지금 보유한 종목만 보므로, 방금 손절된 종목인지 모릅니다.

- **남은 약점은 매수 판단입니다.** 보여 준 후보는 더 이상 나머지보다 나쁘지 않지만, 그중 고른 종목은 무작위보다 못했습니다. 산 종목은 보류한 종목보다 10거래일 뒤 13.3%p 낮았습니다(기준 5.3%p).
